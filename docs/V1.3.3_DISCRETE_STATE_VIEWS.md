## Visualization semantics

Market observations are discrete sampled states.
Straight-line interpolation between historical observations is not interpreted
as an observed continuous market path.

State Map answers “where is the latest state, and where are recent observations
distributed?” It does not imply continuous geometric traversal. Historical
density keeps its existing 32 × 32 bin settings and selected observations.
Older recent observations are unconnected markers, progressively larger and
brighter with recency. Previous is a white open circle; Current is a gold star.
The title includes the full Current Effort, Result and Region label.
Four quadrants and both zero boundaries remain visible.

The only spatial direction vector is Previous → Current. It uses the existing
five-minute/same-segment comparability rule, not a new signal or threshold.
A gap, segment boundary, fewer than two observations or zero displacement has
no arrow. Both markers remain visible where applicable. The arrow describes a
pair of sampled states, not an observed continuous path or trade instruction.

Trajectory defaults to **Effort / Result over Time**, before the existing
chronological ribbon and transitions table. Two vertically aligned panels share
actual timestamps, preserve the exact derived score values, show zero reference
lines, and highlight Previous and Current. Latest ΔEffort and ΔResult reuse the
existing display-summary differences; they are unavailable across discontinuities.
Thin time-panel lines are reading guides, broken at missing bars/segment changes.
They do not connect Effort × Result observations in phase space.

The optional **Advanced: 2D Snapshot Cloud** is collapsed by default. It contains
unconnected points, Previous, Current, one eligible latest-move vector and
quadrants, without density or a full polyline. Advanced State Map is also collapsed.
No additional Region band was added; the existing ribbon is retained once.

Dashboard information architecture, classifications, validation/source routing,
Relay freshness and Archive fallback are unchanged (only the product version
label changes). Legacy `charts.py` / `charts_v12.py` remain byte-identical for
compatibility with older tests/callers, but their polyline functions are **not
reachable from the active v1.3.3 UI**. Tests explicitly forbid those active calls.

## Implementation and verification

- `src/charts_v133.py`: read-only, defensive hosted dtype conversion through
  the existing `state_views` helpers; rendering separated from page functions.
- `src/web_app_v13.py`: route active views to new charts; show existing latest
  differences; change the optional view label; explain discrete-state semantics.
- `tests/test_visual_v133.py`: 48 new cases, including both Relay-shaped and
  Archive-shaped object/string numeric data, shuffled timestamps, exact scores,
  markers, arrow count/endpoints, gap and zero-displacement behavior, zero lines,
  shared timestamp axes, serialization, active page rendering, non-mutation,
  as-of prefix behavior, and protected source hashes.
- The original 206 cases remain. The old accepted-UI pin test is narrowly updated
  to authorize the requested active UI adapter change; mathematical pins and all
  original golden fixtures are unchanged. No old chart tests were removed or relaxed.
- `tests/fixtures/v133_visual_scope_sha256.json` freezes **38** pre-existing
  files from production main: all other `src` modules, both publisher/installer
  scripts, `app.py`, and all three original golden/hash fixtures. Hashes normalize
  CRLF to LF consistently with the existing cross-platform guards. Only the active
  UI adapter has an explicitly versioned new UI hash.
- Python 3.12 CI retains Ubuntu/Windows matrix, compilation and full pytest;
  the push branch list adds this preview branch only.
